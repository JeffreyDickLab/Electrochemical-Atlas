# Electrochemical Atlas

**Electrochemical Atlas** is a local-first reference and study application for a reader's own copy of *Electrochemical Methods: Fundamentals and Applications* (third edition). It combines an indexed catalog, a PDF reader, equation and caption-free figure previews, study paths, bookmarks, notes, and electrochemical calculators.

**Project authors:** Azaria A. Wagner and Jeffrey E. Dick.

The repository **does not include the textbook PDF, extracted page images, saved equation graphics, or figure thumbnails**. It includes only indexing and reviewed figure/equation coordinate locations for cropping. The reader supplies the original PDF, which stays on their computer.

**Figures:** For the supplied third-edition PDF, Atlas uses individually reviewed figure boundaries in the Figures catalog and on each figure detail page. Previews preserve panel letters, axes, legends and labels, and exclude surrounding body text and printed captions. The original caption remains separate below the preview. Figures are rendered from your local PDF in memory; image data is not saved or shipped. Preview boundaries are maintained in the source code, with no user crop editor or saved crop overrides. Other PDFs use conservative detection; when the figure cannot be isolated, **Open in PDF** provides the source. See [Figure previews](docs/FIGURE_PREVIEWS.md) for the coordinate format and maintenance workflow.

The 6 November 2026 review covers **all 564 figures and 565 parts**, including
the two-page introductory figure and the restored label-only Figure 14.9.2.
See [Figure audit](docs/FIGURE_AUDIT.md) for the full coverage record, verification
and browser-testing limitations.

The introductory **Figure 1 (Part 1)** and **Figure 1 (Part 2)** are separate
catalog entries with the same description and their own source-page links.
Their previews use the available width and natural height for easier reading.

**Tables:** All 52 tables in the supplied PDF have reviewed previews. Catalog
and detail previews automatically fit the available width. Select a table and
use its page selector to read any continuation pages. **Open in PDF** follows the table
page currently displayed. The complete catalog covers 81 page parts, including
10 multipage tables. See [Table previews](docs/TABLE_PREVIEWS.md).

## Launch

**Windows:** If `Launch_Electrochemical_Atlas.bat` reports a missing runtime, the archive is incomplete or is the **source-only ZIP**. Download the Windows portable/release archive, right-click it and choose **Extract All**, then run the launcher inside the extracted `Electrochemical-Atlas` folder. The file `runtime/atlas-windows-amd64.exe` must be present. See [README_WINDOWS.txt](README_WINDOWS.txt) for troubleshooting; do not run the `.bat` while it is still inside a ZIP.

**For ordinary users:** Download a portable ZIP from GitHub Releases, extract the complete folder and run the launcher for your operating system. The **GitHub repository source ZIP** contains maintained code and launch scripts but intentionally omits compiled native binaries; build those from Go or use a Release download.

| Platform | Launcher |
|---|---|
| Windows (64-bit) | `Launch_Electrochemical_Atlas.bat` |
| macOS (Apple Silicon or Intel) | `Launch_Electrochemical_Atlas.command` |
| Linux (x86-64 or ARM64) | `Launch_Electrochemical_Atlas.sh` |

Choose your PDF when prompted. The application opens in your default browser at a local address; it is not hosted on an external website. The launcher remembers the **path** to the selected PDF, not a copy of the file. Study data stays in browser storage. Use **Explore**, **Together**, and **Read** to switch between catalog and PDF views.

**Portable first-run ZIP:** Native binaries are included. If PDF.js is not bundled, the launcher downloads the pinned renderer once on first launch while online, then caches it locally. Reading and navigation work without it; cropped figure and equation previews require PDF.js. If it is unavailable, the figure card offers **Open in PDF** rather than embedding a complete source page. **Offline GitHub Releases** generated by the build pipeline include PDF.js and do not require this download.

Runnable packages include the small image decoder needed for the supplied
PDF's compressed graphics. Source-only archives omit generated vendor files;
run the full `npm run build` after installing dependencies for complete figure
previews. A source-only rebuild does not install the missing decoder.

Do not launch `app/index.html` directly through `file://`; PDF workers and locally served resources need the launcher.

## Navigation

The left **Menu** sidebar includes direct **Figures**, **Tables**, **Equations**, **Problems**, and **References** buttons under **Reference library**, alongside Concepts and Symbols. Choose a category to open its searchable catalog in the second column. This also reveals the catalog when the PDF-only **Read** layout is active. On mobile, choosing a destination closes the menu overlay and shows the catalog.

The global search remains available for cross-category queries. **Shift+L** opens the optional compact **Browse** list inside the first column. Select an entry for its detail, **Index ↗** for its full catalog, or **← Menu** to return to the category buttons. Browse remembers its category; each session starts at Menu. Both sidebar views share one persisted width and resize divider, and their entry list uses the same slim scrollbar style as the second column.

Figures, Tables, Equations, Problems and References have a **chapter or appendix
filter** beside their text filter. Front matter is also available. When an entry
is opened from a filtered catalog, its Previous/Next buttons follow those
matches across all catalog pages. Back and the category breadcrumb restore the
filter, page and scroll position. Directly opened entries use the full category.

**Full search** shows the actual result count and 50 results per page. Every
match remains accessible; the inline suggestion list keeps its short display
limit. Back/Forward restores the selected results page. Paging through a search
does not add another Recently Viewed item.

**Recently Viewed** at the bottom of the sidebar keeps the three latest distinct
entries or submitted searches. Reopening an item moves it to the top. The list
is saved locally for the selected PDF and restored when that same PDF is opened
in a later session; typing in the search field alone does not add an entry.

**Symbols & abbreviations** uses clickable entry cards in each of its three
categories. Select anywhere on a card, or focus it and press Enter or Space, to
open the entry. Symbols and standard abbreviations retain each printed meaning
with its own units and section references. Explicit source typography preserves
subscripts, superscripts, bold and script lettering, and overbars. Detail pages
link references that exactly match indexed sections and show their titles;
unindexed suffixes, ranges and table citations remain as printed source text.
Chemical abbreviations display their structure or equation references when the
source table provides them. See [Notation extraction](docs/NOTATION_EXTRACTION.md)
for the source contract and audit coverage.

**Bookmarks and notes** distinguish repeated symbols and are saved separately
for each PDF. Older saved items with one clear destination migrate
automatically. Ambiguous entries and conflicting note versions appear under
**Saved items → Unassigned saved items**, where **Attach note/bookmark** lets
you choose the intended entry. They remain included in exported backups.
Importing a backup merges saved data and preserves differing note versions.

## Features

- Searchable chapters, concepts, symbols, abbreviations, equations, figures, tables, problems, and bibliography entries.
- Matching destinations in the left menu and the search dropdown, including **Chapters**. Search-category previews include an **Open** action for the complete view; **All** lists every menu destination alongside recent activity.
- Original-PDF reading alongside indexed entries, with an **Open in PDF** fallback for ambiguous equation crops.
- Equation, figure and table previews produced at runtime from the user's own PDF using local PDF.js rendering.
- Adjustable reading layouts, source-specific bookmarks and notes, study paths, and scientific calculators.
- Cross-platform portable launchers with local-server lifecycle management.

## Privacy, source fidelity, and limitations

- The Atlas checks the selected PDF's SHA-256 fingerprint before using edition-specific equation locations. Unmatched PDFs do not receive those previews.
- All equation images are rendered **in memory**. The repository and ZIP packages contain no copied equations or source pages.
- A coordinate-only manifest identifies the equation locations; a small number of overlapping symbols and surrounding prose may still require inspection in the original PDF. The printed PDF remains authoritative.
- The selected PDF is served by a local process bound to `127.0.0.1`. No PDF, study notes, or extracted text is sent to a remote Atlas service.
- Only a first launch without bundled PDF.js may access a third-party CDN to download the PDF.js **program files**. The selected PDF is not transmitted in that process.

## Development

The maintainable code lives in `src/client/` (web UI) and `src/launcher/` (Go launcher). The checked-in `app/` directory is generated runtime output. **Change source files, not generated files.** See [Architecture](docs/ARCHITECTURE.md) and [Contributing](docs/CONTRIBUTING.md).

Requirements: Node.js 22.13+ and Go 1.23+. For a production/offline build:

```sh
npm ci --ignore-scripts --omit=optional
npm run format:check
npm run test:all
go test ./src/launcher
npm run release
```

The lockfile pins development and runtime dependencies. Use `npm run format` after editing maintained JavaScript, CSS or HTML, and `npm run format:check` to check consistency without changing files. The formatter understands the application files that share one closure; coordinate JSON and scientific text inside template strings are left unchanged. Then rebuild `app/` before testing.

`npm run release` compiles all five launchers and creates the full offline bundle. Use `npm run release -- --platform windows`, `macos`, or `linux` to build one offline download. A version tag pushed to GitHub starts three independent jobs, each of which uploads its own ZIP after passing validation. The exact `pdfjs-dist` version is pinned in `package.json` and checked against the first-run launcher version.

For a repository-only checkout without downloading npm packages:

```sh
npm run build:source
npm run check
npm test
go test ./src/launcher
npm run package:source
```

`build:source` does not install third-party PDF.js modules. It preserves an already
installed renderer if one exists, so refreshing the maintained source doesn't
silently disable equation previews. The source ZIP still excludes vendor files. The **source package excludes compiled binaries**; to run it locally, build a native launcher for your current platform with Go, or use the portable ZIP. For browser testing, install Playwright/Chromium, then run `npm run test:browser`
to execute the portable synthetic test suite. Set `ATLAS_CHROME` to a Chromium executable if needed and
`ATLAS_BROWSER_ARTIFACTS` to change where ignored screenshots are written.
The end-to-end test `tests/browser/smoke.py` also requires `ATLAS_TEST_PDF` to
point to your locally owned textbook; it never bundles the PDF. See
[Release validation](docs/RELEASE_VALIDATION.md). Structural tests alone do not
prove that every equation is visually perfect.

To produce a launcher for your current platform from source, create `runtime/` and run `go build -o runtime/atlas-<OS>-<ARCH>[.exe] ./src/launcher`, substituting your target names (such as `atlas-linux-amd64` or `atlas-windows-amd64.exe`). The full `npm run release` pipeline builds all five automatically.

## Scientific typography and source fidelity

The interface formats source-derived chemical notation, powers, indices, units,
and explicit Unicode superscripts/subscripts **for display only**. This is
shared by figure/table captions, problem statements, references, symbol cards,
search previews, and calculator model descriptions. The underlying extracted
strings, index/search data, and original PDF are not changed. Bibliographic
page ranges are not inferred to be mathematical powers. If a PDF font lacks a
reliable Unicode mapping or a flattened mathematical expression is ambiguous,
the app preserves the available source text instead of inventing typography.
Use **Open in PDF** to verify complex equations, structures, tables, and
citations in the authoritative source.
